# 视觉主链路实验 Batch 01：原图、网格、粗到细与 UI Tree 辅助

日期：2026-07-22

## 1. 结论先行

本批次完成 8 个不同真机任务 × 7 种配置 × 3 次重复，共 168 个 task-run、190 次 GUI-Plus API 调用。

- 在这组受控任务上，`grid10__vision_only` 为 24/24，是本批次最高结果；
- 不能据此宣称“10×10 网格普遍优于原图”：数据集只有 8 个、界面风格单一，且每个配置只有 24 次；
- 原图纯视觉为 21/24，错误点击 3 次；原图 + Tree 辅助为 22/24，错误点击 2 次，但 Tree Critic 没有拦截这两次错误，因为错误点落在非可点击空白/文本区域；
- 粗到细没有体现收益：纯视觉 19/24、Tree 辅助 20/24，模型调用和 Token 约翻倍，主要新增失败来自第二次调用的格式错误；
- `tree_first` 为 23/24、只调用模型 3 次，是当前成本和延迟最强基线；唯一失败发生在 UI Tree 不可见的 Canvas，视觉 fallback 点到搜索按钮并被 Tree Critic 正确拦截；
- UI Tree 辅助在本批次没有证明稳定提升视觉成功率。它真实拦截了一次错误，但该次属于 `tree_first` 的视觉 fallback；视觉优先的 Tree 辅助配置没有发生拦截。

这些结果只代表 **MobilePilot Lab 第一批受控任务上的定位表现与重复运行结果**，不代表商业 App、开放世界任务或通用手机操作的泛化成功率。

## 3. 模式隔离审计

- `vision_only`：任务初始化后只请求截图；72/72 条记录的 `ui_tree_requests_after_setup=0`；
- `vision_with_tree_aux`：先用纯截图产生视觉候选，之后才允许读取 UI Tree 做冲突检查和验证；
- `tree_first`：决策前读取 UI Tree，语义目标缺失时调用原图视觉 fallback；
- 目标真实边界只用于执行后的离线评分，不进入 Prompt；
- 视觉模型原始输出、解析结果、候选坐标、是否执行、错误点击和 Tree 请求数均保存在 JSONL。

## 6. Verifier 假阴性审计

原始严格截图指标曾将 16 个 `results_filter` 正确点击记为 `post_action_screen_unchanged`。原因是该动作只改变一行文字，全屏平均像素差分别可能低至 0.09～0.33，旧阈值为 1.0。

独立执行三次确定性诊断：

- 三次均在 UI Tree 中读到“当前筛选：评分 4.5 以上”；
- 截图差异得分为 5.79、0.33、0.09；
- 因此这 16 条在派生矩阵中标为 `success_after_verifier_audit`；
- 原始 `runs.jsonl` 保持不变，`summary.json` 同时保留 `strict_screenshot_task_success_rate` 和审计后的 `task_success_rate`；
- 后续运行的截图阈值降为 0.05，并新增数值 `image_change_score`，不再只保存布尔结果。

## 7. 典型失败案例

### 7.1 原图定位筛选按钮发生纵向偏移

`raw__vision_only` 在 `results_filter` 第 1 次运行输出归一化点 `[473,310]`，映射为 `(595,868)`；真实按钮范围为 `(70,587)～(1190,755)`。模型描述理解正确，但纵向坐标偏低，执行后形成错误点击。

### 7.2 Tree Critic 真实阻止一次错误点击

`tree_first` 在 Canvas 任务第 3 次视觉 fallback 输出 `[505,337]`，映射为 `(636,943)`，实际落在 `search_button`。Critic 检测到视觉候选覆盖了可点击语义控件并拒绝执行。正确 Canvas 范围为 `(85,1198)～(1175,1469)`。

### 7.3 粗到细增加输出协议失败面

一次粗定位正确找到调试按钮，但第二次局部调用返回：

```text
{"action": "left_click", {"coordinate": [507, 518]}}
```

这是畸形 JSON，解析器拒绝执行。粗到细需要两次均成功，因此它在本批次增加了调用数、Token、延迟和格式失败概率，没有换来更高成功率。

### 7.4 模型省略 action

一次输入框任务只返回 `{"coordinate":[499,273]}`，没有 `action`。系统按协议错误记录并停止，没有猜测或补写动作。

## 8. 对项目路线的影响

1. 继续以视觉主链路作为项目特色；第一批结果支持保留 10×10 网格作为高优先级候选，但不能提前宣布它是最优方案；
2. 原图保留为必要基线；
3. 当前固定比例粗到细方案暂停扩展，在分析裁剪区域、第二阶段 Prompt 和结构化输出稳定性之前，不进入默认路径；
4. UI Tree 辅助继续只用于候选后的 Critic/Verifier。当前没有足够证据把它设为视觉模式的默认配置；
5. `tree_first` 继续作为强工程基线和消融参照，不改变项目视觉优先定位；
6. 下一批任务应扩大视觉差异，而不是继续扩建设备层：增加图标、密集小目标、相似干扰、不同纵向区域和状态失效任务。
