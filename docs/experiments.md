# Experiments and Technical Decisions

本页记录对最终设计影响最大的实验结论。历史实验来自有限离线任务和特定视觉模型，不应被理解为对所有 GUI Agent 的普遍定律。

## Prompt length and rate limits

早期版本不断向 Prompt 添加规则，输入长度和输出长度随之增加，连续任务更容易触发 API 限流。后续版本删除重复说明、缩短示例，并把提示聚焦到坐标计算、输入流程和完成条件。

工程结论：Prompt 的价值不在于“规则越多越好”，而在于模型是否能稳定抓住少数关键约束。

## JPEG and PNG

早期使用 JPEG 压缩截图，希望减少视觉 Token；后期版本切换为 PNG，避免小文字和细图标被压缩模糊。不同模型的视觉计费和图像预处理方式可能不同，因此仓库只保留“当前实现选择 PNG”的事实，不把它扩展为所有模型都成立的结论。

## Five-stage and three-stage parsing

五层解析器曾尝试从任意文本中搜索 JSON、关键词和数字。它提高了“总能返回某个动作”的概率，也可能把普通文本中的数字误判为坐标。

最终版本只保留：

1. 标准动作格式；
2. 已知函数式格式；
3. 安全终止。

工程取舍是降低错误恢复的覆盖面，换取更高的动作可信度。

## Self-Correction

实验版本曾在首次决策后再次调用同一模型进行审查与修正。它偶尔能发现错误，但也会推翻正确动作，并带来额外 Token、延迟和随机性。最终实现删除了该链路，每个步骤仅调用一次模型。

## Scenario-specific rules

针对外卖、视频、地图和订票等场景尝试过动态特判。少量运行中部分任务有改善，但结果方差较大，难以将变化单独归因于规则本身。当前代码保留通用 Prompt，历史特判文本仅作为实验材料存在，未被 `agent.py` 动态加载。

## Evaluation discipline

视觉模型在相同输入下仍可能出现不同决策。后续实验应至少重复运行多次，并同时报告最佳值、均值、方差和失败类型，而不是只引用单次最高分。
