# Failure Analysis

## Coordinate drift

最常见问题是动作类型正确，但点击坐标落在目标框外。典型模式包括：

- 搜索图标位于右上角，模型却输出靠近屏幕中央的安全点；
- 纯文字按钮的估算框包含过多留白，导致 Y 坐标偏下；
- 坐标落在评测框边缘，而评测器使用严格不等式判断。

对应措施是视觉网格、强制中心点计算和坐标后处理。它们只能降低常见偏移，无法替代真正的 UI 元素检测器。

## Premature or delayed completion

Agent 有时在格式异常时过早输出 `COMPLETE`，也可能在结果已经出现后继续进入详情页。前者是安全降级的代价，后者说明模型对“用户目标是否已满足”的判断不稳定。

## Input and search flow

不同 App 的搜索体验并不统一：有些页面进入后光标已激活，有些需要再次点击；输入后可能出现目标联想项，也可能必须点击键盘搜索键。过度僵化的“TYPE 前后固定动作”容易在特定 App 上失败。

## Popup and layout variation

广告弹窗、权限弹窗、版本更新和推荐内容会改变页面结构。离线截图只能覆盖少量布局，无法模拟真实 App 的持续变化。

## API and infrastructure errors

限流、鉴权、账户余额和网络异常都会被上层观察为 `COMPLETE` 或空动作。实际产品应区分“任务完成”和“基础设施失败”，并提供重试、错误码和可观测性；当前比赛接口为了安全结束流程，使用了更简单的降级策略。

## Next evaluation improvements

- 建立不依赖比赛数据的公开任务集；
- 对同一任务重复运行并统计方差；
- 分别报告动作类型、坐标命中和端到端任务成功率；
- 将 API 错误与 Agent 决策错误分开统计；
- 为失败 Trace 保存脱敏截图、原始输出和解析结果。
